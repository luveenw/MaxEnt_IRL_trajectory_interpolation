# One biome reward model with separate computational maps

Research recommendation, 2026-10-30; validation workflow clarified 2026-11-01. This note addresses how to combine evidence from spatially separated Pantanal groups. It does not implement training, choose experiment groups or animal splits, or change the locked selector/report. The user clarified that groups are computational units, not intended ecological populations.

## Recommended initial architecture

Fit **one shared biome reward parameter vector**, while calculating route probabilities on separate local maps. With a fixed common feature definition, use `r_theta(s; map) = theta^T f_map(s)`. Each demonstration keeps its own map, endpoints, horizon and historical covariate period. Different maps may have different numbers of cells. The reward function is shared; the resulting policies vary with local habitat and route conditioning.

This is a direct extension of the feature-based conditional MaxEnt likelihood, whose gradient compares demonstrated and model-expected feature totals. [Ziebart et al. (2008), Learning from Demonstrated Behavior and Eq. 6](https://www.cs.cmu.edu/~bziebart/publications/maximum-entropy-inverse-reinforcement-learning.pdf). Learning one reward across environments also has explicit IRL precedent: [Nakata and Arai (2019)](https://doi.org/10.1527/tjsai.B-J23) jointly constrain a shared reward using multiple environments, although their algorithm is linear-programming IRL rather than this project's MaxEnt method.

For this project, apply the already specified animal/window/step objective in §6 of [the consolidated specification](pantanal_sampling_time_and_grid.md). In compact notation, optimize `sum_j w_j log P_theta(route_j | map_j, start_j, goal_j, horizon_j)` with fixed, documented weights. This is a recommendation derived from the modeling goal, not a claim that a cited paper validates the particular jaguar weighting scheme.

An efficient implementation can load one map or a bounded batch at a time, compute its expected feature counts, accumulate the weighted gradient, and release its large arrays. It need not construct a whole-biome grid or hold every group's dynamic-programming arrays in memory simultaneously. At prediction, apply the shared reward to a map covering the requested route problem.

## Comparison of the proposed approaches

### Prediction averaging

An ensemble is a possible secondary comparison: for a common query `q`, define `P_mix(route | q) = sum_g alpha_g P_theta_g(route | q)`, where nonnegative weights sum to one. The models must all be evaluated on the **same query map/support, endpoints, horizon protocol, feature definitions and preprocessing**, not simply reuse their original local prediction arrays. A model restricted to one local map cannot directly predict a route elsewhere.

Average probability distributions or sample from the mixture; averaging coordinate sequences may create a route that no component predicts and may cross excluded cells. Averaging reward vectors is generally different from averaging predictions because planning and probability normalization are nonlinear. Independently fitted rewards may additionally have nonidentifiability, different regularization or incompatible scaling. Multiple-environment identifiability and transfer require conditions, rather than following automatically from having many experts: [Rolland et al. (2022), §§1–2 and feature-based extension](https://proceedings.neurips.cc/paper_files/paper/2022/file/03bdba50e3741ac5e3eaa0e55423587e-Paper-Conference.pdf).

Ensembles can express heterogeneous predictions, but neither better calibration nor improved accuracy is guaranteed. Validate weight choices using held-out animals and an explicitly defined target. Equal computational-group weights are not naturally justified: splitting one group into two could change the prediction without adding any observations. Sampling-duration weights change the target toward long-monitored animals; they do not automatically correct uncertainty or achieve equal animal representation.

### Train each group to convergence in succession

This does not optimize the pooled objective. Once earlier data are removed from the objective, later updates are selected to improve the current group's fit, potentially degrading earlier fits. If each group has a unique optimum and is fitted fully, the last fit can largely determine the result; with finite optimization, initialization and order can also matter. This conclusion follows directly from changing objectives and does not depend on invoking neural-network forgetting.

Warm starts are useful computationally, but must be followed by optimization of the **joint** objective if the goal is a biome model. Retaining earlier examples for replay or revisiting all groups in shuffled repeated epochs can achieve that. There is no need to train and permanently save a separate final reward for every batch.

### Joint training with sequential computation — recommended

Two valid implementations are:

1. **Full-gradient passes:** fix theta, evaluate every selected animal/window contribution at that theta, sum weighted gradients, then update theta once. Group evaluation order has no substantive effect apart from floating-point accumulation. This gives bounded-memory computation without changing the objective.
2. **Repeated minibatches:** shuffle/revisit groups or, preferably, sample animals/windows according to the intended weights, and update theta after batches. Correct unequal batch sampling probabilities where necessary. This approximates pooled optimization; order, learning-rate schedule and finite stopping can affect numerical results, so use fixed seeds and monitor global validation performance.

For fixed features, fixed path support and linear rewards, the correctly evaluated negative conditional MaxEnt log-likelihood is a weighted sum of log-sum-exp terms minus linear terms, hence convex for nonnegative fixed weights; convex regularization preserves that property. This is a mathematical inference for this declared model. It does not establish uniqueness without additional conditions, nor apply automatically to nonlinear rewards, latent-path EM, parameter-dependent support, or the unverified legacy implementation. Inspect and repair that trainer before relying on convergence claims.

## Weighting, duplication and ungrouped animals

- Use unique original animals as the top-level weighting units, then unique accepted windows within each animal, as already proposed. Do not give extra weight simply because an animal appears in many generated candidate groups.
- Candidate groups are overlapping alternatives, not 253 independent datasets. Choose one map context per included animal/window by default, or document how duplicate contexts divide a fixed evidence weight. Merely deleting identical array filenames is insufficient: the same source events may have different row/column indices in different maps.
- Preserve global animal-level train/validation/test assignments across all groups and variants. Spatially blocked validation is additionally useful when the target is transfer to new parts of the biome; animal-disjoint splitting alone does not establish that target.
- An otherwise eligible animal outside a multi-animal cluster can use its own bounded local map and contribute to the same reward objective. It need not be assigned an artificial ecological group. Data-quality, route-support, covariate availability and computation limits still apply; absence from the current selection is not permission to bypass them.
- Equal-animal weighting targets the average represented animal, not uniform geographic coverage or an unbiased estimate for all Pantanal jaguars. If broad geographic representation is a separate aim, specify and validate a spatial weighting scheme independently of arbitrary computational group boundaries.

## Required common contracts

Keep common feature names/order, units, categorical encoding and training-fitted scaling across maps. Avoid per-map normalization that changes the meaning of the same theta coefficient. Match cell size, action semantics, barriers, diagonal rules, reward convention, entropy scale and horizon protocol. Preserve historical map periods. Local bounds alter available routes and partition functions, so adequate padding and boundary sensitivity remain modeling issues even when grouping was motivated only by memory constraints.

One shared reward is a biome-level working hypothesis and may average real sex, behavioral, seasonal or regional differences. Assess residual/held-out performance before adding a hierarchical model such as shared biome coefficients plus regularized animal/region deviations. Those are future modeling decisions, not requirements for the checkpoint/export task.

No new training, weighting, split assignment, group selection or model averaging is implemented by this research note.


## Validation design for a small animal cohort

The user confirmed that **both new-animal and new-area generalization must be evaluated**. These are separate experiments with separate fold manifests and performance summaries. The following is a recommended protocol, not an assignment of animals or an implemented trainer. Fold counts remain conditional on the final eligible cohort and geographic support.

### Background and sample size

There are 56 Pantanal animals in the source cohort, but the current immutable selection checkpoint `selection_8cc3315f50f9395c0e399726` has 117 returned candidate windows and only **20 unique represented animals**, also 20 in generated-group membership. Do not design or label an experiment as n=56 unless all 56 actually contribute eligible evidence. The 253 overlapping computational groups do not increase the independent animal count.

Use the original animal ID as the ownership unit across every window, subtrajectory, group/map context, sampling representation and gap/grid sensitivity. Construction of a new fragment does not establish biological independence. Individual-level replication is consistent with the population-inference discussion in [Fieberg et al. (2010)](https://pmc.ncbi.nlm.nih.gov/articles/PMC2894958/).

A permanent 20% test set is **optional**, not a prerequisite for K-fold validation. The recommended starting design uses outer grouped cross-validation for assessment, with inner grouped validation only when choosing hyperparameters or other data-driven settings. Each animal is tested once per outer partition. The outer test results assess the prespecified selection procedure; repeatedly redesigning the procedure after viewing those results consumes their independence. The separation of inner selection and outer assessment is explained in the [official nested-CV example](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html).

With all 56 eligible, a reasonable starting point is five outer animal folds (11–12 test animals, 44–45 development animals), and three inner folds among the development animals. With the currently represented 20 animals, start by assessing feasibility of four outer folds (5 test/15 development) and three inner folds (about 10 fitting/5 validation within development). These are proposals, not statistically guaranteed optimal counts. Reduce tuning breadth or prespecify settings if inner fitting sets cannot support the model. A small number of animals/sites limits inference regardless of telemetry volume. Repeated outer partitions can diagnose split sensitivity, but repetitions do not create independent animals.

If a permanent untouched test is specifically wanted instead, use the alternative protocol below; do not silently add it on top of the recommended nested design.

### First-run seasonal selection

For each initial training experiment, choose one collection from one season in the separate seasonal pipeline. Individuals may contribute week-long windows anywhere within that season plus its seven-day buffers, including different calendar years. Core seasons are winter May 15–August 14, spring August 15–November 14, summer November 15–March 21, and autumn March 22–May 14. Entire sampling windows must fit within the buffered period. Sampling duration and buffers are separately configurable. See [the seasonal workflow](../../jaguar_irl/data/README_PANTANAL_SEASONAL.md) for exact contracts and selection rules.

Treat the named season as restricted by this design: it is not an additional fold-stratification variable within that experiment. Preserve exact dates, month/year coverage and out-of-core buffer exposure as diagnostics, and construct environmental maps for those dates. A season can contain substantial within-season hydrological variation; this restriction does not establish equal flood conditions across dates, years or sites. Compare separate seasonal models using their actual contributing populations. Pooling seasonal experiments would require an explicitly different design.

Collection alternatives are alternative cohorts, not additive batches. Use the collection's canonical export ownership to avoid repeated or overlapping windows; keep all evidence from the same original animal in the same fold. All computational groups within one seasonal experiment share one reward parameter vector and one feature definition/scaling contract, using the pooled objective below. Group membership changes local maps and computation, not the identity of the fitted biome-and-season reward. The first seasonal report has 9, 15, 16 and 12 represented animals in winter, spring, summer and autumn respectively before export-specific route exclusions; choose fold counts from eligible exported animals and available geographic blocks, not the full 56-animal source cohort.

### Step-by-step workflow

1. **Define the experiment and eligible evidence.** State whether prediction means another animal within represented areas or an animal in an unseen area. Freeze the source checkpoint, evidence eligibility, window rules, endpoint/horizon protocol, evaluation reference and candidate settings before viewing model performance. Record all 56 IDs and exclusion reasons, but use contributing animals to calculate fold sizes. Geographic and animal experiments may use the same source cohort while answering different questions. Structured validation should follow the prediction target: [Roberts et al. (2017)](https://doi.org/10.1111/ecog.02881).
2. **Build a descriptive animal ledger.** Store animal ID, sex/unknown, study/project name, geographic site/block, full monitoring span, selected observed exposure, windows by exact dates, covered calendar months and year, actual interval distribution, planned schedule when known, gap frequency, fragmentation and eligible contribution counts. Separate full-record span from actual training exposure. Site is a geographic definition, not automatically a project name. For each initial run, enforce the single-season collection restriction above instead of assigning season strata. Full-record seasonal exposure outside selected windows is not a fold-balancing criterion. Publish this balance information without using held-out prediction outcomes.
3. **Assign new-animal outer folds with limited balance priorities.** Keep animals indivisible and fold counts approximately equal. Prefer approximately balanced sex counts and representation of geographic sites that have enough animals. Use a seeded random allocation within coarse categories, or a prespecified search over allocations scored only by metadata imbalance. Avoid sex × site × cadence × duration Cartesian-product strata. Cadence, duration and year are initially diagnostics/soft balance criteria, not mandatory matched cells. Season is already restricted by first-run window selection and is not a fold-balancing variable. Rare sites/sex categories may make balance impossible; document that limitation rather than splitting an animal or manufacturing replication. Freeze the seed, allocation algorithm, priorities, imbalance score and resulting animal manifest before fitting. Do not select the split with the best model score.
4. **Assign separate geographic outer folds.** Define meaningful non-overlapping geographic sites/blocks before outcome inspection; hold out one area, or a prespecified set of areas, at a time. Keep all evidence from each held-out animal out of training, including records outside its held-out area. For animals spanning blocks, use a documented rule such as excluding them from that particular contrast; never divide the same animal between sides. If geographic separation requires a buffer, justify and freeze it, and exclude boundary-neighboring training evidence as specified. Report actual train/test distances and covariate overlap; do not claim spatial independence from site labels alone. Do not force a 20% animal count or sex balance by breaking a geographic block. Site count and geometry determine feasible folds. Current computational group IDs/MCP overlaps are not geographic validation units. For strict geographic transfer, use an externally defined test map/domain rather than tailoring its bounds to the complete held-out route. The current full-study MCP domain supports a known-domain interpolation claim unless separately redesigned.
5. **Tune using the outer development data only.** For each outer split, fit every candidate from scratch in inner training folds and select settings by animal-averaged inner validation scores. Reuse the same inner folds across competing methods. Use animal-grouped inner folds for the new-animal experiment; prefer geographic inner folds for geographic transfer when enough development sites remain. If too few sites remain, prespecify settings or state explicitly that inner tuning is animal-based and only the outer assessment measures geographic transfer. Fit feature scaling, feature selection, any learned horizon calibration, stopping decisions and other fitted preprocessing only on the applicable inner training set. Gap-threshold alternatives require separately versioned downstream artifacts; they do not authorize changing the locked selector. Fixed, outcome-independent QC may be applied consistently to all sides. For paired fine/two-hour comparisons, retain the same animal assignments and evaluation cases.
6. **Refit and test each outer fold.** After choosing settings without its test animals/area, refit one shared reward from scratch on all that fold's development evidence. Refit transformations there as well. Score the held-out test cases without choosing settings, maps, endpoints or operational horizons from hidden reference paths. Save predictions and animal-level metrics. Never initialize a fold from a model already trained on that fold's held-out animals. Fixed shared target cases allow paired method comparisons; separately report coverage and exclusions for each method's full eligible cohort.
7. **Summarize assessment and inspect heterogeneity.** Combine out-of-fold animal scores with equal-animal weighting for the represented-animal target; do not average fold means equally when fold sizes differ unless explicitly targeting folds. For geographic transfer, report each area's result and distinguish an equal-area summary from an equal-animal summary. Report sex/site/cadence/duration subgroups with their actual sample sizes, without demanding inferential claims for tiny cells. Report each seasonal experiment separately; retain within-season dates/months/years and buffer exposure as provenance. Use animal-level uncertainty for new-animal assessment and geographic-unit uncertainty for geographic transfer when enough units exist. Do not treat fragments, repeated folds or repeated windows as independent replicates. Track both error and retained cohort/coverage under sampling/gap sensitivities; also compare common eligible cases. If sex, site and collar cadence are confounded in the data, balanced folds do not identify their separate effects.
8. **Fit the deployment model after assessment.** Apply the prespecified inner-CV selection rule to the full eligible cohort, select settings, and train one final shared reward on all eligible evidence. Retain outer out-of-fold results as the assessment of the training procedure at its evaluated training sizes; do not claim an independent test of the exact final all-data fit. Do not average outer-fold reward vectors to create the deployment reward. If outer results prompt substantive redesign, call the next analysis exploratory or obtain a genuinely new assessment sample/protocol.

### Alternative: a permanent 20% test set plus development folds

If this alternative is chosen explicitly:

1. Once eligibility is fixed, select about 20% of **animals**, using a seeded metadata-only allocation with the limited priorities above. At n=56, 11 animals is 19.6% (45 remain); a tool rounding upward may choose 12 instead, so record the convention. At n=20, four held-out animals provide a particularly uncertain final test. No IDs are chosen in this note.
2. Seal those animals and all their evidence. Perform grouped validation folds only within the other approximately 80% to choose settings. Validation folds rotate; the sealed test animals do not.
3. Refit from scratch on the entire 80% with selected settings and evaluate the sealed 20% once. Any subsequent tuning informed by that test makes it development evidence.
4. For a permanent geographic test, select complete areas instead of forcing exactly 20% of animals. To reserve both geographic and within-area animal tests simultaneously, declare disjoint test pools and recognize the further loss of development animals; this is not the default for the small present cohort.

The permanent-test approach is easier to explain but reserves scarce animals and gives a result sensitive to a single small test sample. Nested grouped CV is the recommended starting assessment here. Neither approach guarantees balanced or representative data.

## Exact shared-reward computation contract

The recommendation combines **training evidence/gradients under one reward parameter vector**. There is no post-hoc operation that averages separately fitted group rewards in the default architecture. Let the reward on group map g be `r_theta(s; g) = theta^T f_g(s)`, using the same feature definitions/order/units and training-fitted scaling on all maps. Historical map periods, action rules, barriers and conditioning remain explicit.

For each fit (inner, outer refit, or final deployment):

1. Start with only that fit's training animals. Choose one declared map context per unique animal/window evidence by default. Resolve overlapping windows/source-event or source-edge duplication; do not concatenate all overlapping candidate groups. An otherwise eligible isolated animal can contribute on its own local map. Do not pool independent and paired exports as additional independent demonstrations.
2. For each animal i, let `W_i` count its included informative windows. For a window w, let `T_iw = sum_s L_iws`, where L is a contributing segment's spatial-move count. Let N count animals with such contributions. Maximize the declared objective:

   `J(theta) = (1/N) sum_i (1/W_i) sum_w [(1/T_iw) sum_s log P_theta(tau_iws | map_iws,start_iws,goal_iws,L_iws)] - lambda R(theta)`.

   Every segment receives coefficient `c_iws = 1/(N * W_i * T_iw)` on its log-likelihood and empirical/expected feature totals. Do not additionally divide by segment count. This makes each animal's total weighted model-step mass 1/N. Exclude zero-move and proven unique-route cases from this optimizer and its normalizers, but preserve their diagnostic records; do not replace zero denominators by one. For paired fine/two-hour experiments reconcile contributing animals/windows first, then calculate each arm's own T. This weighting is a project choice targeting represented-animal/window average per-step fit, not a theorem of MaxEnt or a population-representativeness guarantee.
3. Initialize theta and any optimizer state fresh for this fit. Hold theta fixed for a full-gradient pass. Load each local map in turn, compute each assigned demonstration's empirical feature totals minus its conditional model-expected totals at that same theta, multiply by c, and accumulate into one gradient. Release large local arrays as needed. Add the regularization gradient once for the whole objective, then make one theta update after the full pass. Do not regularize once per map unless its weights explicitly sum to the intended single penalty.
4. Repeat passes until the training/validation stopping rule is satisfied. Save the shared theta, feature/scaler contract, regularization, evidence weights, map bindings, fold manifest and hashes. At prediction, construct the requested map's features with the saved contract and plan using this theta. Local policies differ because environments and conditioning differ, despite sharing theta.
5. A repeated shuffled-minibatch implementation is an alternative optimization of the same objective, with correct sampling weights and regularization. Sequentially fitting each group to convergence once is not this objective and can favor later groups. Unit-test accumulated gradients against a small pooled calculation and finite differences before production use; the legacy trainer remains unverified and requires its separately scoped repairs.

## Locked selector versus downstream export: threshold reminder

Code inspection on 2026-11-01 confirms two deliberately distinct policies. The locked selector/report must not be described as if it already implements the export-only policy.

**Locked `movement_processor_pantanal.py` / `pantanal_temporal.py` selection:**

- Scan complete seven-day candidate periods from actual fix times, allowing month/year boundaries. Thin to actual observations: retain the first fix, then choose the fix closest to +2 hours within inclusive [1.5,2.5] hours (ties earlier). If none exists, take the earliest available fix at least 1.5 hours later. Closer intermediate fixes are skipped. No synthetic fixes or fixed global clock are introduced.
- A selected gap in [1.5,2.5] hours is regular. A selected gap in (2.5,4] hours may remain inside a segment. Count its two endpoints, counting a shared endpoint once. Across all retained segments require `A/M <= 0.20`, where M is the entire candidate period's thinned point count before segmentation/removal. This is not 20% of edges or 20% independently within each segment.
- Gaps >4 hours always split; exactly four hours is not a compulsory cut. If needed to meet the pooled affected-point budget, split at additional (2.5,4]-hour edges. Cutting removes that edge from A; its endpoint still counts if another retained irregular edge touches it. Cuts alone preserve observations.
- Partition to maximize retained points, with the implemented tie priorities; only fragments below five observations may be discarded. Reject the candidate if discarded fragments exceed 5% of M, or no qualifying fragment remains. This legacy 5% cap implies at least 95% retention relative to M for accepted selector candidates; it is an indirect consequence of that cap, not the later export policy.
- Main candidates also require at least `ceil(0.80 * (round(7*24/2)+1)) = 68` final retained fixes against the 85-fix two-hour reference and at least 6.5 days first-to-last retained span. The reference is computed from configured duration/interval, not a literal hard-coded 68. Relaxed candidates may violate density/span and carry measured flags; cadence, segmentation and the 5% loss cap remain protected. Full-record span and supported-month counts are currently descriptive only.

**Separate `export_pantanal_irl.py` / `pantanal_irl_temporal.py`:**

- Fine representation keeps original source cadence; gaps >4 hours and tag changes split source bouts. Short source fragments remain cataloged; the default five-source-observation screen controls array eligibility. It does not resample fine evidence to [1.5,2.5] hours.
- The two-hour comparison representation uses observed-point thinning, the [1.5,2.5] regular band, >4-hour hard cuts, pooled `A/M <= 0.20`, and five-point retained fragments. Require nonempty retained evidence; final F/M is diagnostic by default (`--min-final-retention 0`), with an optional minimum such as `.8`; there is **no separate 5% loss cap or 85-fix schedule-density gate**. Fine evidence survives comparison failure. These export settings do not expand or regenerate the checkpoint's selected cohort.

No selector, checkpoint, backing file, HTML, visualization, split assignment or training implementation is changed by this research-note update.


## Clarification: source-preserving checkpoint and two export treatments

Clarified with the user, 2026-11-01. The request to retain observations finer than 1.5 hours is already covered by the planned unthinned primary source and the existing exporter's **fine** representation. The redundant upcoming-processor amendment has been removed. It does not create a new primary 2.5-hour eligibility bound or change the four-hour source gap guard. The first-run seasonal collection restriction above applies.

The actual data path is:

1. The locked selector uses its thinned tracks to choose eligible windows/groups and generate its existing report. This is **selection of periods and members**, with a thinned representation used for that selection.
2. `pantanal_checkpoint.write_selection_checkpoint` receives the original parsed records as well as those selected windows. For each returned candidate's start/end interval, it retrieves **all original parsed source records** in that interval using timestamp bounds, not just `window["points"]`. It writes these to `source_points.csv` and links them through `window_events.csv`. Fine fixes skipped by selection thinning therefore remain available. This checkpoint is limited to returned windows: it does not restore animals/windows excluded by the old selector.
3. `jaguar_irl/data/export_pantanal_irl.py` reads those source observations from the checkpoint (`window["events"]`). It creates two alternative treatments from the same source evidence: **fine**, using original cadence, and **two_hour**, recomputing the explicitly defined standardized comparison treatment. It does not recover fine fixes from an already-thinned trajectory, and it does not thin a thinned input a second time. Arrays are subsequently gridded/compressed under their common spatial contract. Source evidence and event provenance remain recorded.
4. The export-only F/M gate is optional and disabled by default (`--min-final-retention 0`); `.8` restores the former minimum. M is the comparison sampler's selected observations before segmentation; F is its final count after segmentation and dropping short fragments. Always require nonempty retained evidence and report F/M; it is **not the fraction of raw observations retained by thinning** or expected-schedule coverage. The fine treatment has no such ratio gate.

The locked selector keeps its 5% fragment-loss cap plus main-week density/span checks. Export-only settings do not relax or expand that selected cohort. The exporter originally enforced the later F/M >=80% specification, but on 2026-11-01 the user authorized making this redundant final check optional; it now defaults off. Existing artifact manifests preserve their original settings.
